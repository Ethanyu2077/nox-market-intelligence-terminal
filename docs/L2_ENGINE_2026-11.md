# 序列校验 L2 引擎 / Sequenced L2 engine

连续盘口与 REST 快照严格分离：`orderbook.ts` 仍是单次快照（2s TTL），本模块维护「REST 快照 + 增量」的连续状态。

## 状态机

`connecting → syncing → live → (gap/stale) → resyncing → live`

- 任何缺口、断线或重连都会进入 `resyncing`，拒绝继续套用增量，直到新的 REST 快照完成重建。
- 快照与增量之间的缓冲在 `syncing` 期间保留（上限 2000 条），快照应用后按序重放；重放中出现缺口则重新同步。
- 12 秒没有新消息标记 `stale`；断线指数退避重连。

## Venue 序列规则（实测差异）

| Venue | 规则 | 缺口检测 |
| --- | --- | --- |
| Binance | 快照 `lastUpdateId`；首条增量必须 `U <= last+1 <= u`；之后 `pu` 必须等于上一条 `u`；`u <= last` 丢弃 | ✅ |
| OKX | 快照 `seqId`；增量 `prevSeqId` 必须等于上一个 `seqId`；`seqId` 相同为重复；`prevSeqId=-1` 视为快照标记；`action:"snapshot"` 重建；带 `checksum` 的帧用 CRC32 校验前 25 档 | ✅（checksum 失败 → 强制重同步） |
| Bybit | `u` 单调递增但**不连续**；`type:"snapshot"` 必须重建订单簿；`cts` 作为事件时间；不做缺口推断 | ❌（依赖重连/重同步，文档明确） |

OKX checksum 已实现：对前 25 档 `bidPx:bidSz:askPx:askSz` 计算 CRC32，失败时 `integrity=checksum-failed` 并强制重同步。

`L2Snapshot` 新增 `verified` 与 `lastValidUpdate`：`live` 只代表有数据流；OKX 在 checksum 通过前 `verified=false`。UI 用 `live*` + 「未验证」明确标注，未确认完整性的订单簿不会被当作可信 Live。

## 指标

按 25bps 深度窗口计算：mid、spread bps、买卖深度（USD）、不平衡、（相对上一采样）买/卖盘撤出百分比。指标与快照同帧经 SSE 推送，历史仅保留内存 600 点，不落盘。

## 接口

- `GET /api/market/:exchange/:symbol/book` → `{ snapshot, metrics }`（binance/bybit/okx）
- `GET /api/market/:exchange/:symbol/book/stream` → SSE `book` 事件，250ms 一帧
- 连接按 `venue:symbol` 引用计数复用；最后一个订阅者断开后关闭。

## 界面

Market Structure 的盘口面板新增一行 L2 状态：状态、序列号、缺口/重同步计数、失衡、买卖撤出、完整性。REST 快照梯子与连续 L2 指标同时展示，并各自标注边界。

## 已知边界

- Binance 连续流依赖 `fapi/v1/depth` 快照；本机测试环境对 Binance REST 有间歇性阻断，引擎与解析已由单元测试覆盖，实机验收需可访问 Binance 的网络。
- 连续 L2 历史不持久化（与 REST 快照、本地成交带分开）；研究模块不应把它当作可回放历史。
- 没有隐藏/冰山流动性，深度不等于大单可执行规模。
